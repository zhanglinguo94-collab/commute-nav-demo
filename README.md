# 通勤异常主动导航助手

> 基于地图实时信息、路线收益与用户偏好的主动导航服务 Demo

**🌐 Live Demo：** [部署后填写 Vercel 地址](#)<br>
**📦 GitHub：** [https://github.com/zhanglingluo94-collab/commute-nav-demo](https://github.com/zhanglingluo94-collab/commute-nav-demo)<br>
**项目类型：** 地图业务 / 主动服务产品设计<br>
**Demo 数据：** Mock 数据，不接入真实地图与实时交通 API

---

## 1. 产品背景

对于熟悉固定通勤路线的用户，大多数轻微路况变化并不值得主动打扰。

真正有价值的问题不是“是否发现了异常”，而是：

**这次异常对当前行程影响有多大、是否存在明显更优路线，以及此刻是否适合主动提醒用户。**

因此，本项目以：

**地图事实 → Rule Gate → 介入价值判断 → Remind / Silent → 用户确认 → 路线重新校验**

为核心链路，探索地图主动服务如何在“有价值时介入、无价值时保持安静”。

---

## 2. 核心用户

高频驾车通勤用户，尤其是：

- 已熟悉固定或半固定通勤路线；
- 日常不会持续关注导航信息；
- 突发严重拥堵时，需要快速判断是否值得改变原路线；
- 希望减少低价值导航提醒和不必要操作。

---

## 3. 核心场景

用户正在熟悉的通勤路线上行驶。

前方突然出现严重拥堵，导致原本稳定的通勤时间明显增加。

系统基于地图提供的实时路况、当前路线和候选路线数据进行评估：

- 如果候选路线收益明显；
- 数据可信；
- 当前驾驶环境适合提醒；

则向用户提供简洁的绕行建议。

如果收益不足或存在安全风险，则保持 Silent。

---

## 4. 核心用户问题

传统导航能够提供路况与重新规划能力，但驾驶中的用户仍然需要回答三个问题：

1. 这次异常到底会影响我多少时间？
2. 换路线是否真的值得？
3. 当前是否适合打断我并提出建议？

产品目标不是增加提醒数量，而是：

**提高每一次主动提醒的价值。**

---

## 5. MVP 范围

### MVP 内

- 通勤路线突发严重拥堵识别；
- 原路线与候选路线收益比较；
- Rule Gate 安全与数据有效性检查；
- Remind / Silent 介入决策；
- 极简提醒解释；
- 用户确认后路线切换；
- 执行前二次路线校验；
- 用户接受 / 拒绝 / 无响应反馈记录。

### MVP 外

当前版本不覆盖：

- 停车、加油、充电等其他主动服务；
- 非通勤临时出行；
- 多目的地复杂规划；
- LLM 自行生成 ETA、交通事件或路线等地图事实；
- 未经用户确认自动切换路线。

---

## 6. 产品流程

```text
地图异常事件
↓
获取当前路线与实时路况
↓
地图生成候选路线
↓
Rule Gate
↓
介入价值判断
↓
Remind / Silent
↓
生成极简解释
↓
用户确认
↓
重新校验候选路线
↓
地图执行路线切换
```

其中：

**用户拒绝或无响应 → 保持当前路线。**

## 7. MAP / RULE / AI / USER 能力边界

### MAP｜地图确定性能力

负责提供：

- 交通事件；
- 当前路线；
- ETA；
- 候选路线；
- 距离与路线收益；
- 路线重新规划与切换执行。

Demo 中以上数据均使用 Mock 数据模拟。

### RULE｜产品策略能力

负责：

- 数据有效性检查；
- 驾驶复杂度判断；
- 安全门控；
- 路线收益判断；
- Remind / Silent 决策。

Rule Gate 可以直接阻止主动提醒。

### AI｜智能能力

AI 不负责生成或修改地图事实。

当前 Demo 中主要用于：

- 基于已确认事实生成极简用户解释；
- 为后续个性化偏好理解预留能力。

### USER｜用户决策

用户拥有最终路线切换权。

在用户明确确认之前，系统不得自动改变当前路线。

---

## 8. 四个 Demo 场景

### 场景 A｜高收益介入

前方事故导致原路线预计延误 18 分钟。

候选路线预计可节省 13 分钟。

Rule Gate 通过后系统主动提醒；用户确认后，再次校验候选路线有效性，随后执行路线切换。

### 场景 B｜低收益静默

候选路线仅节省约 3 分钟，同时增加额外行驶距离。

介入价值不足：

**Silent。**

用户不会收到主动提醒。

### 场景 C｜安全门控

候选路线虽然具有明显收益，但车辆距离复杂交叉口仅约 120m。

Rule Gate 阻止当前提醒。

驶离复杂驾驶区域后，系统重新评估是否仍值得介入。

### 场景 D｜用户拒绝

系统提出绕行建议后，用户选择继续当前路线。

系统：

- 不执行路线切换；
- 保持当前导航；
- 记录本次行为反馈。

---

## 9. 验证框架

当前 Demo 主要进行场景级与逻辑级验证。

测试覆盖包括：

- 应提醒 / 不应提醒；
- 路线收益不足；
- 驾驶复杂度过高；
- 数据置信度不足；
- 无有效候选路线；
- 用户接受；
- 用户拒绝；
- 用户无响应；
- AI 超时；
- 地图能力失败；
- 用户确认前路况变化；
- 二次路线校验失败。

重点检查：

- 无效打扰；
- 漏提醒；
- Rule Gate 是否正确拦截；
- 地图事实是否保持一致；
- 用户确认前是否存在错误切换；
- 异常情况下是否能够安全降级。

### 上线后重点指标

真实上线后需要进一步建立基线并验证：

- 有效提醒率；
- 提醒接受率；
- 路线切换确认率；
- 用户拒绝率；
- 无效打扰率；
- 漏提醒率；
- 二次路线校验失败率。

当前 Demo 不提供真实线上指标，  
相关目标值需根据线上基线进一步确定。

## 10. Demo 边界说明

本项目用于展示主动导航服务的产品逻辑和业务中台能力设计。

当前版本：

- 使用模拟地图与 Mock 数据；
- 未接入真实高德 / 百度 / Google Maps API；
- 未使用真实用户历史行为数据；
- 不代表实际线上导航系统。

Demo 的重点不是复现完整地图基础设施，而是验证：

**主动介入策略、能力边界、异常流程与用户确认机制。**
